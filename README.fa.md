# صبر · sabr

**دانلودی که هیچ‌وقت از صفر شروع نمی‌شود.**
`git clone`، `docker pull` و دانلود فایل، قابل‌ادامه، برای اینترنت کند، محدودشده و ناپایدار.

[وب‌سایت](https://mrzroot.github.io/sabr/) · [English](README.md) · [نسخه‌ها](https://github.com/mrzroot/sabr/releases)

## مشکل

`git clone` همه یا هیچ است: یک بسته، یک اتصال؛ اگر اتصال در ۹۷٪ قطع شود همه‌چیز دور ریخته می‌شود و
باید از صفر شروع کنید. `docker pull` هم با یک لایه‌ی ۶۰۰ مگابایتی همین کار را می‌کند. روی فیبر نوری
کسی متوجه نمی‌شود، ولی روی اینترنت همراه، مسیر بین‌الملل کُند‌شده، ماهواره یا هر جایی که اتصال پایدار
نیست، گاهی کلون کردن یک مخزن بزرگ عملاً غیرممکن می‌شود.

**صبر** کار را به تکه‌های کوچک تقسیم می‌کند و هر تکه به محض رسیدن ذخیره می‌شود؛ پس قطعی فقط چند ثانیه
هزینه دارد، نه کل دانلود. یک فایل اجرایی تنهاست که با همان `git` خودتان کار می‌کند و مستقیم با رجیستری
داکر حرف می‌زند. سرور، حساب کاربری یا تنظیمات لازم ندارد.

خود نصب‌کننده‌ها هم در صورت قطعی ادامه می‌دهند، هش SHA-256 فایل را با نسخه‌ی منتشرشده چک می‌کنند و
دسترسی root یا admin نمی‌خواهند.

## استفاده

| به‌جای | اجرا کنید | وقتی اتصال قطع شود |
|---|---|---|
| `git clone URL` | `sabr clone URL` | فقط همان قدم کوچک تکرار می‌شود؛ قبلی‌ها حفظ می‌شوند |
| (Ctrl+C، ری‌استارت، تمام شدن باتری) | دوباره همان `sabr clone URL` یا `sabr resume DIR` | از `.git/sabr.json` ادامه می‌دهد |
| `git pull` | `sabr pull` | fetch با تکرار، فایل‌های جاافتاده دسته‌دسته، بعد fast-forward |
| `docker pull IMG` | `sabr docker pull IMG --load` | لایه از همان بایتی که قطع شد ادامه می‌یابد |
| `curl -O` / `wget` | `sabr get URL --sha256 HEX` | ادامه با Range، تشخیص تغییر فایل، بررسی هش |

</div>

```sh
sabr clone https://github.com/torvalds/linux
sabr clone --depth 50 https://github.com/torvalds/linux
sabr docker pull python:3.12-slim --load
sabr docker pull docker.arvancloud.ir/redis:7 --load        # با آینه‌ها هم کار می‌کند
sabr get https://nodejs.org/dist/v24.21.0/node-v24.21.0-linux-x64.tar.xz --sha256 …
```

### خودتان امتحان کنید

`sabr chaos` عمداً یک شبکه‌ی خراب می‌سازد: پروکسی محلی که هر اتصال را بعد از چند مگابایت قطع می‌کند.
هر ابزاری را به آن وصل کنید و مقایسه کنید. همین آزمایش در CI روی GitHub، Docker Hub و nodejs.org
واقعی، در هر push اجرا می‌شود.

</div>

```sh
sabr chaos --cut 2MB &
git -c http.proxy=http://127.0.0.1:8899 clone https://github.com/cli/cli     # هر بار شکست می‌خورد
HTTPS_PROXY=http://127.0.0.1:8899 sabr clone https://github.com/cli/cli      # تمام می‌شود
```

## چطور کار می‌کند؟

کلون در چهار مرحله‌ی قابل‌ادامه انجام می‌شود، همه با `git` خود شما (نسخه‌ی ۲.۲۹ به بالا):

۱. **آخرین کامیت** بدون محتوای فایل‌ها (shallow و blobless).
۲. **تاریخچه از جدید به قدیم، در قدم‌های رشدکننده.** هر قدم موفق برای همیشه ذخیره می‌شود. بعد از موفقیت
قدم دو برابر و بعد از قطعی نصف می‌شود؛ پس اندازه‌ی قدم خودش را با چیزی که اتصال شما بین دو قطعی
می‌رساند تنظیم می‌کند.
۳. **فایل‌های آخرین کامیت، دسته‌دسته،** با درخواست مستقیم شناسه‌ی هر blob. اگر حتی یک فایل تکی هم رد
نشود (مثلاً فایل ۲ گیگابایتی روی اتصالی که هر ۵۰ مگ قطع می‌شود)، صبر آن فایل را از
`raw.githubusercontent.com` با Range دانلود می‌کند و با `git hash-object` ذخیره و شناسه‌اش را دقیقاً چک می‌کند.
۴. **checkout** با lazy fetch خاموش، تا هیچ‌چیز بی‌صدا به دانلود یک‌جا برنگردد.

نتیجه یک مخزن git معمولی با تاریخچه‌ی کامل است. به‌طور پیش‌فرض partial clone است (نسخه‌های قدیمی فایل‌ها
هر وقت لازم شد دانلود می‌شوند)؛ با `--all-blobs` همه‌چیز از اول، در همان دسته‌های قابل‌ادامه، دانلود می‌شود.

**docker pull** مستقیم با API رجیستری کار می‌کند، پلتفرم شما را از ایمیج‌های چندمعماری انتخاب می‌کند،
هر لایه را با Range در یک کش مشترک دانلود و SHA-256 را چک می‌کند و آرشیوی می‌سازد که `docker load`،
containerd و `podman load` می‌پذیرند. با Docker Hub، GHCR، رجیستری خصوصی و آینه‌هایی مثل
`docker.arvancloud.ir` کار می‌کند.

## چه چیزی واقعاً تست شده؟

- در CI، روی GitHub واقعی (`cli/cli` با بیش از ۸۰۰۰ کامیت) از پشت پروکسی‌ای که هر ۲ مگابایت قطع می‌کند:
`git clone` معمولی شکست می‌خورد و صبر دقیقاً به همان HEAD می‌رسد.
- Docker Hub واقعی (`python:3.12-slim`) از پشت همان پروکسی، سپس `docker load` و `docker run`.
- تست‌های end-to-end با `git daemon` واقعی: نتیجه‌ی یکسان با مخزن اصلی، `kill -9` وسط کار و ادامه،
`sabr pull`، مخزن ناموجود سریع خطا می‌دهد.
- نصب‌کننده‌ها روی لینوکس، مک و ویندوز (PowerShell 5.1 و 7)؛ فایل دستکاری‌شده نصب نمی‌شود.

## محدودیت‌ها

- صبر فیلترینگ یا تحریم را دور نمی‌زند؛ فقط کاری می‌کند اتصالی که دارید تا آخر برسد.
- روی اتصال بی‌نقص کمی کندتر از `git clone` است، چون به‌جای یک درخواست بزرگ چند درخواست کوچک می‌فرستد.
- submodule ها بعد از کلون با `git submodule update` معمولی گرفته می‌شوند.
