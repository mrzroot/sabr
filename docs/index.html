Downloads that
never start over.

git clone, docker pull and big downloads are all-or-nothing: one dropped connection at 97% and you start again from zero. sabr splits them into small, resumable steps, so a drop costs a few seconds instead of the whole download. It even survives a reboot.

curl -fsSL https://mrzroot.github.io/sabr/install.sh | sh

The installer is resumable too, and it checks SHA-256. Single static binary; only needs git (for clone) and nothing else.

git clone→sabr clone
docker pull→sabr docker pull --load
curl -O→sabr get --sha256
In one sentenceدر یک جمله

sabr downloads like a patient traveller: it moves in small steps and remembers where it stopped, so when the connection drops, git clone, docker pull or a big file carries on instead of starting from zero.

صبر مثل یک مسافر صبور دانلود می‌کند: قدم‌به‌قدم جلو می‌رود و یادش می‌ماند کجا ایستاده؛ پس وقتی اینترنت قطع می‌شود، git clone، docker pull یا یک فایل بزرگ از همان‌جا ادامه پیدا می‌کند، نه از صفر.

Time is sped up. Each tool's behaviour is simplified: git restarts the pack from zero after a drop; sabr loses only the step in flight, retries with backoff and halves the step size.






  
How sabr clone works

  
    
    
  1. 1
    Latest commit
    A blobless, depth-1 fetch: just commits and folders, a few hundred KB.
    2. 
    
  2. 2
    History, in steps
    It deepens history step by step. The step size doubles after a success and halves after a drop.
    3. 
    
  3. 3
    Files, in batches
    It lists the missing blobs and fetches them in adaptive batches. Any file that keeps failing is downloaded by byte range and hash-checked.
    4. 
    
  4. 4
    A normal repo
    Then it checks out, sets the upstream and origin/HEAD, and you have the same result as git clone. Progress is saved in .git/sabr.json, so a kill or reboot just resumes.
    5. 
  

  

    
sabr docker pull
Talks to the registry directly, resumes each layer from the byte it stopped at, and keeps a shared layer cache. It writes a docker load archive; add --load to load it into Docker or Podman. No daemon changes.
$ sabr docker pull python:3.12-slim --load
  ✓ 41.3 MiB, 39 resumes

    
sabr get
Byte-range resume across runs. It restarts if the file changed on the server, has a stall watchdog, and verifies SHA-256.
$ sabr get https://nodejs.org/…/node.tar.xz \
    --sha256 3b1c…

    
sabr chaos
A built-in bad link: a local proxy that cuts or freezes every connection after N bytes. Use it to test your own tools.
$ sabr chaos --listen 127.0.0.1:8899 --cut 2MB

FAQ
Questions people askپرسش‌های پرتکرار
Does sabr bypass filtering or sanctions?صبر فیلترینگ یا تحریم را دور می‌زند؟
No. It makes the connection you already have go further: it downloads in small pieces and keeps every piece that arrived.نه. همان اینترنتی را که دارید بیشتر به کار می‌گیرد: تکه‌تکه دانلود می‌کند و هر تکه‌ای را که رسید نگه می‌دارد.
What if my laptop restarts halfway?اگر وسط کار لپ‌تاپم خاموش شد چه؟
Run the same command again. sabr continues from the last piece it saved instead of starting over.همان دستور را دوباره اجرا کنید. صبر از آخرین تکه‌ای که ذخیره کرده ادامه می‌دهد و از اول شروع نمی‌کند.
Is it slower on a good connection?روی اینترنت خوب کندتر است؟
A little. It makes many small requests instead of one big one. On a bad connection that is the difference between finishing and not.کمی. به جای یک درخواست بزرگ، چندین درخواست کوچک می‌فرستد. روی اینترنت بد، همین فرقِ تمام شدن و نشدن است.
Does it work with Docker and Podman?با داکر و پادمن کار می‌کند؟
Yes. sabr docker pull IMAGE --load sends the image straight into Docker or Podman. It works with Docker Hub and other registries.بله. sabr docker pull IMAGE --load ایمیج را مستقیم به داکر یا پادمن می‌دهد. با Docker Hub و رجیستری‌های دیگر کار می‌کند.
Only GitHub, or any git host?فقط گیت‌هاب یا هر سرور گیتی؟
Any git host. One limit: a single huge file inside a repository arrives over git in one piece. For github.com sabr fetches such a file in byte ranges; other hosts need the connection to last for that one file.هر سرور گیتی. یک محدودیت: یک فایل خیلی بزرگ داخل مخزن، از راه گیت یک‌تکه می‌رسد. برای github.com صبر چنین فایلی را بازه‌به‌بازه می‌گیرد؛ در سرورهای دیگر اتصال باید برای همان یک فایل دوام بیاورد.
